### 2. REGLAS COMPLETA DE CONTROL DE EXISTENCIAS E INVENTARIO
El comportamiento lógico del inventario responde a directrices estrictas diseñadas para preservar la coherencia entre lo que la aplicación muestra y la disponibilidad física real del saldo:

* **Regla de Unicidad por Código de Fábrica (STK-01):** El sistema impide la creación paralela de dos registros de saldos diferentes con el mismo código de barras universal. Si el usuario intenta registrar una zapatilla cuyo código ya habita en la base de datos, el flujo de creación se interrumpe de inmediato. En su lugar, el sistema redirige la interfaz del usuario hacia la pantalla de edición del registro preexistente, permitiendo únicamente el incremento de unidades en la matriz de tallas o la modificación del precio.
* **Regla de Consistencia en Tallas (STK-02):** Todo saldo dado de alta requiere obligatoriamente que al menos una de las tallas de su matriz posea una cantidad de existencias superior a cero. Las tallas deben interpretarse exclusivamente como cadenas de texto plano, neutralizando cualquier intento de alteración por redondeo matemático que ocurre comúnmente al procesar números fraccionarios en informática.
* **Regla de Ocultamiento Dinámico y Liquidación (STK-03):** La interfaz visual que genera los catálogos rápidos para enviar a WhatsApp consulta la matriz en tiempo real. Si el valor numérico de existencias de una talla específica se reduce a cero, dicha talla se remueve de forma automática de las opciones seleccionables del catálogo. Si la totalidad de las tallas vinculadas a un producto llega a cero, el saldo se declara automáticamente como "Liquidado", ocultándose por completo de las pantallas operativas de venta diaria, pero manteniéndose intacto en el archivo interno para no dañar los reportes históricos de los pedidos previamente completados.

### 3. PROCEDIMIENTO Y ALGORITMO DE FUSIÓN INCREMENTAL POR CABLE LOCAL
Ante las restricciones operativas de los teléfonos móviles con sistemas operativos modernos que impiden la asignación automática de una letra de unidad de disco tradicional al conectarse por USB (operando bajo el protocolo de transferencia multimedia), el sistema implementa un procedimiento de unificación de datos bidireccional coordinado desde la aplicación de escritorio en Windows mediante los siguientes pasos narrativos:

#### 3.1 Etapas del Flujo de Unificación de Datos
1. **Establecimiento del Canal Físico:** El operador enlaza el dispositivo móvil a la computadora de escritorio mediante un cable físico USB y configura manualmente los permisos del teléfono para autorizar la transferencia de archivos.
2. **Localización Guiada del Almacenamiento:** El usuario activa la función de sincronización en la aplicación de Windows. Esta acción despliega una ventana de navegación nativa del sistema operativo que exige al operador buscar y seleccionar manualmente la carpeta del almacenamiento interno del teléfono donde reside la base de datos móvil. Esto concede al motor de Windows los accesos de lectura y escritura requeridos.
3. **Lectura Paralela en Memoria:** La aplicación de Windows extrae de forma simultánea el contenido de su propia base de datos local (denominada Base Maestra) y el contenido de la base de datos extraída de la carpeta del teléfono (denominada Base Móvil), cargando ambas estructuras en la memoria volátil del procesador para su evaluación comparativa.
4. **Resolución Cronológica de Conflictos Registro por Registro:** El motor de fusión recorre elemento por elemento las listas de saldos, clientes y pedidos de ambas bases de datos. Ante elementos que compartan el mismo identificador único, el sistema aplica la Regla de Conflictos Basada en Tiempo: compara las marcas de tiempo de modificación o actualización con precisión de milisegundos. El registro que posea el instante de tiempo más reciente sobreescribe por completo al registro más antiguo, independientemente de si el cambio ocurrió primero en la computadora o en el celular.
5. **Tratamiento de Registros Huérfanos:** Si el motor encuentra un identificador que existe en la Base Móvil pero está ausente en la Base Maestra (como un calzado registrado en movilidad), lo añade directamente a la lista unificada. En sentido inverso, si un pedido fue modificado o creado en la computadora de escritorio y no figura en el teléfono, se inserta en el flujo de datos consolidado destinado al dispositivo móvil.
6. **Escritura Atómica en Bloque:** Concluido el análisis en la memoria RAM, el sistema genera un único conjunto de datos consolidado y ejecuta dos operaciones de escritura secuenciales e inmediatas: reemplaza el archivo local de la computadora y, acto seguido, reemplaza el archivo en el almacenamiento del teléfono a través del canal del cable conectado, garantizando que ambos dispositivos terminen con copias idénticas del mismo archivo de texto plano.
7. **Sincronización Binaria de Archivos Multimedia (Imágenes):** El motor analiza las carpetas de fotografías de ambos extremos. El sistema inspecciona los nombres de los archivos de imágenes y calcula el identificador digital único del contenido binario (huella digital criptográfica) de cada fotografía. Si se detecta un identificador digital en el teléfono que no se encuentra físicamente en la carpeta de la computadora, el archivo de imagen se transmite a través del cable hacia el disco de escritorio. Si la computadora posee fotos nuevas editadas, estas se transmiten en dirección inversa hacia el dispositivo móvil, unificando visualmente ambos entornos.
